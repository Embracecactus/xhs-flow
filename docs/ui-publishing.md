# WSL2 图文上传与发布流程

适用范围：已有终审版本和发布包的单篇小红书图文。Agent 与文件校验留在 WSL2，优先复用可用会话；必要时调用经审批的 Windows 浏览器与 UI Automation。本文整理 2026-10-10 的实际操作经验，不提供发布 API、无人值守发布器或跨平台框架。页面名称和控件以当次现场为准。

前置制作、导出与作者审核沿用 [本地操作手册](workflow.md)。本流程从已有发布包开始，不重新制作素材。

## 1. 续跑先确定本次允许做到哪一步

读取 `xhs-workspace/account.md`、本篇 `state.json`、审核记录、最新操作结果和 `publish/<版本>/manifest.json`。旧记录保留为历史，以最新明确指令判断本次范围。

| 用户授权 | 可以推进的范围 | 停止位置 |
| --- | --- | --- |
| 仅制作或审核 | 文件制作、预览、校验 | 本地交付 |
| 上传与填写，不发布 | 指定账号的本篇上传、填表、声明设置和回读 | 编辑页；不点击最终发布 |
| 明确要求发布 | 本篇已确认版本的最终提交及结果核验 | 本篇结果确定；不扩展到其他笔记 |

明确授权且内容未变时不重复询问。后来的“只上传”会收窄范围；再后来的明确“发布”可以授权最终提交。曾经发布成功不构成下一篇的授权。账号、版本或稿件变更影响原授权时，先说明变化，再处理相应确认。

只补真正缺少的信息，例如本篇是否存在商业合作；已有回答直接复用。网络、登录和账号确认有记录时不重复整套诊断，但执行前仍须从当前目标窗口读到账号。

## 2. 将操作权限和技术能力分别核实

先读已有协议诊断和证据，记录协议名称、官方地址、版本或读取时间、具体条款及其与本次操作的关系。没有发布 API、SDK 不适用，不能单独证明界面自动化被禁止；启动浏览器、工具可控或提交成功，也不能证明该方式得到平台许可。

已有原文限制确实适用且没有可核实例外时，停止受限的自动操作，可继续校验和交付供本人操作的材料；不以 Windows GUI、模拟点击、换工具或重复取得同一用户授权解决平台限制。原文无法取得则写“未核实”，不冒充已经确认。

本项目的历史记录曾确认创作中心协议对自动化访问的限制，后续实际上传与发布记录未补入适用例外依据。技术成功已取得，但这项适用性问题没有闭环；本篇不能直接作为未来自动发布的许可凭据。具体官方证据和本篇事实保留在本地工作区，不再循环搜索同一批 API、SDK。

## 3. 实际读取目标会话

1. 发现当前浏览器/桌面工具与已有会话；现有会话可用就继续。旧工具句柄失效只证明该句柄不能续接，不能推断用户从未登录。
2. 现有工具不能控制时，再检查 WSL 调用宿主程序及已有 Windows UIA/浏览器连接能力。所有需要审批的调用走正常审批。
3. 枚举顶层浏览器窗口和标签，读取目标页面地址、标题、实际账号及操作区域。只检查 `MainWindowHandle` 不能代表已检查全部窗口。
4. 将后续操作限定在已确认目标窗口。窗口句柄、坐标、控件位置每次重新发现，不复用历史常量；点击前核对目标，动作后等待实际界面状态变化并回读。
5. 当前页面确需用户登录时由本人完成。遇到验证码、访问拦截或限流，保留现场交由本人处理，不绕过。不要为切换到 Windows 而强制更换已可用会话。

“可控制”的证据必须来自目标后台：能读取实际账号和目标编辑区域，并能在授权范围内操作后回读。浏览器启动、本地测试页成功、仅看到 Chrome 窗口都不足以证明目标后台可控。

不得接管日常浏览器配置、导出或解密 Cookie、暴露调试端口、关闭全部浏览器或干扰其他窗口。原始工具错误应记录操作、时间、退出码和具体报错，不能统称“WSL2 不支持”。

## 4. 核对素材并顺序上传

先核对 ZIP、包内清单及批准版本的逐文件哈希。实际上传只使用编号图片；联系表、预览页、源码、审核记录不是上传素材。读取包内的标题和纯文本正文，不临时改稿，不覆盖旧导出。

Windows 文件对话框使用实际可访问的 Windows 路径，例如 `\\wsl.localhost\<发行版>\<项目路径>\<上传目录>\01.png`；不要直接填 `/home/...`。需要本地暂存时仅复制本篇文件，复制前后核对哈希，不搬迁整个项目。

在图文编辑入口按包内编号顺序选择全部图片，打开前回读文件列表，上传后等待完成。核对：

- 图片数量与包一致；六图是本篇数量，不是平台固定要求。
- 第 01 张为封面，全部缩略图的版式顺序与本地联系表对应。
- 无重复、缺图或仍在上传的占位项。

顺序证据可以是有序文件选择加缩略图对应；如只核验了封面，不声称已逐张查看其余图片的大图。预览切换失败不能成为重复上传的理由。

## 5. 填写标题、正文和声明

标题逐字填写并回读。正文使用批准包内的纯文本，保留段落、空格、标点和话题；等待编辑器完成更新后再比较。不能因为调用返回成功就判定写入成功。

富文本编辑器的 `ValuePattern.SetValue` 可能压平换行；逐键输入可能触发话题补全而改变正文。需要粘贴时先确认编辑区焦点；使用系统剪贴板须事先完整备份可恢复的格式，完成后恢复，不记录原剪贴板内容。若不能可靠备份/恢复，暂停该方式并保留现场。

正文验收采用文本回读与截图互证：逐行比较非空文本，单独检查空段落；空格、标点、话题必须一致。UIA 省略空行与实际正文丢失换行是两种情况，不能简单删除全部空白后宣布一致，也不能只凭字数一致通过。

| 字段 | 操作与验收 |
| --- | --- |
| 商业关系 | 依据本篇已确认事实处理；未知不能自动填“无合作”。 |
| AI 内容声明 | 按实际创作方式选择平台提供的选项，回读选中结果；原创声明不能替代 AI 声明。 |
| 原创声明 | 用户要求且素材事实支持时，读取当次须知及确认弹窗，完成同意与“声明原创”，回读开关状态；不承诺平台一定授予原创保护标识。 |
| 合集 | 用户指定则按指定；只要求加入合集时，从现有合集选择与内容明确匹配的一项并告知，存在实质歧义再询问。新建合集需单独判断授权。 |

自定义开关的 UIA `IsOffscreen` 和坐标可能与视觉状态不一致。结合当前弹窗、标签、相邻控件、可用 Pattern 和截图确认归属后操作；不能无差别切换所有 CheckBox，也不能只因 `IsOffscreen` 为真就认定控件不存在。

## 6. 回读完成后按授权停留或提交一次

提交前保存截图和简短记录，包含账号、篇目/版本、素材摘要、授权原意、图片数量/顺序、标题、正文比较、商业事实、AI 声明、原创开关、合集、核验时间及适用条件结论。字段齐全不替代权限与适用条件核实。

如果只获上传授权，停在编辑页并说明“已上传并填写，未提交审核”。没有实际保存及后台回读证据时，不称为“已保存草稿”；不要额外点击“暂存离开”。

已有最终发布授权且各条件满足后，确认准确的最终按钮，只提交一次，立即记录调用时间及返回结果。点击后超时、空白、跳转或 `published=true` 都不是重复点击的依据。发生工具中断时按“提交结果未知”恢复，先查后台。

## 7. 从后台判定结果并回填

| 报告阶段 | 最低证据 | 不能据此推断 |
| --- | --- | --- |
| 可控制 | 目标窗口、账号、目标区域实际读回 | 已上传 |
| 已上传 | 数量和顺序核验，标题正文及声明回读 | 草稿持久化、已提交 |
| 已提交审核 | 后台出现对应标题/封面/时间的审核中条目 | 已公开发布 |
| 已发布 | 本篇进入后台已发布列表；取得对应真实链接或作者明确确认后本地登记 | 已完成公众端全文或跨账号可见性测试 |

打开笔记管理，用标题、封面、时间共同匹配本篇。搜索无结果时清空搜索，检查“全部”“审核中”“已发布”等对应列表；审核中列表消失可能是状态变化，不能直接判定提交失败。核验到审核中时可以如实交付，不承诺审核时长，不无限轮询。

从本篇卡片取得真实链接后记录稳定笔记地址；不把会话参数或凭据写入报告。公众站点要求登录时不为证明登录态而重复登录；后台状态、公众端已读范围和未验证部分分别说明。

项目状态枚举不新增“上传中”“审核中”。尚在审核时保留 `待发布`、`publication: null`，在单篇过程记录中写实际阶段，续跑先读该记录以免重复提交。已取得真实发布链接后使用现有本地命令：

```bash
python3 scripts/xhs.py published <篇目ID> --url 'https://www.xiaohongshu.com/explore/<实际笔记ID>'
```

此命令校验批准版本并登记本地状态，不执行平台发布。无链接时，只能使用作者明确给出的发布确认，不能由 Agent 编造确认文本。

## 常见故障与恢复

| 实际现象 | 判定与处理 |
| --- | --- |
| `Unknown process id` | 旧工具进程已失效；重新发现可用会话，不认定登录失败。 |
| `UtilBindVsockAnyPort ... socket failed 1` | 记录沙箱内失败，按正常审批核验宿主调用；不能据此断言 WSL 无法调用 Windows。 |
| `.ps1` 返回 `SecurityError / UnauthorizedAccess` | 保留执行策略错误，不修改 ExecutionPolicy 或使用 Bypass；只在明确允许的调用边界内继续，不能把被拒操作换写后绕过。 |
| 跨进程 Edit 的 `GetWindowText` 读空 | 不据此判定文件列表为空；在已授权目标对话框使用 UIA 或可读的 `WM_GETTEXT` 交叉确认。 |
| 正文换行变平、话题自动补全 | 停止提交，恢复批准纯文本并重新回读；不以改写稿件掩盖输入错误。 |
| 剪贴板恢复异常 | 记录错误，不反复覆盖剪贴板；确认原内容状态及可靠恢复能力后才继续。 |
| 点击缩略图未切换预览 | 记录实际核验范围，保留有序文件选择和缩略图证据，不重传。 |
| 提交后搜索不到 | 清除筛选并检查对应后台列表，核对标题/封面/时间，不再次提交。 |

## 保存与下次续跑

账号、截图、后台数据及操作证据只写被 Git 忽略的 `xhs-workspace/posts/<篇目ID>/`。每轮记录真实时间和阶段；最新结果提供入口，旧证据保留为历史，不覆盖成稿和原上传包，不自动提交或推送。

建议结果记录包含：控制情况、图片及正文核验、声明与合集、最终提交次数、后台状态、发布链接、截图位置、实际错误与未验证项。屏幕/日志采集只保留完成本篇所需内容，不记录 Cookie、密码、验证码或无关剪贴板数据。

下次可使用以下任务描述，替换占位项后给出本篇授权：

> 按 docs/ui-publishing.md 续跑 `<篇目ID>/<版本>`，账号 `<目标账号>`，素材 `<已核验包>`。本次授权为 `<仅上传填写 / 上传并发布>`。商业关系 `<本篇事实>`，原创声明 `<要求>`，合集 `<指定项或按内容选择现有合集>`。先读取最新结果和协议证据，核验内容未变及当前目标窗口；结果不明先查后台，不重复提交。最终回报实际阶段、截图和已取得的链接。
