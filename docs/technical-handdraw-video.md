# 技术手绘讲解视频制作 SOP

入口：[technical-handdraw-video](../skills/technical-handdraw-video/SKILL.md)。本流程沉淀本项目 I²C 手绘片的实际制作方法：WSL2 内完成脚本、绘图、合成与核验，剪映原生界面生成指定配音，最终由手绘引擎输出视频。它不是“剪映导出整片”流程，也不把其他 Remotion 工程的经验替换进来。

## 1. 确定本次产物与版本

读取项目 README、账号偏好、任务状态、当前脚本/分镜/来源/审核及最新用户反馈。已有确定要求直接复用，不重复选择方向、风格或是否检查。用户只要分镜则交付分镜；要求完整成片则推进到有声视频和审核包。

本项目用户明确常用横屏 4K，当前默认画布为 16:9、3840×2160；帧率沿用任务，本例30fps。旧交接中的9:16、1080×1920不覆盖后来修改。GG侠来自本次明确声音要求，不能将某一次音色选择推广为所有未来作品的强制规则。

| 工作类型 | 应修改的层 | 需要保留的内容 |
| --- | --- | --- |
| 新片 | 主题、主张、脚本、视觉、声音、时间线 | 所用资料来源与授权 |
| 竖转横/4K | 页面布局、文字/图示、封面、字幕位置 | 未变的技术脚本和已认可音频 |
| 换配音 | 分段音频、停顿、时长、动作与字幕 | 未变的技术结论、图像及画幅 |
| 某术语读错 | 受影响音段及下游时间线 | 其他音段及已通过的视觉源 |

旧版本只读，另建新版本，记录旧关键文件哈希并在交付时复核。引擎原生任务目录和生产 CLI 不一定兼容；本例 `flow.py revise` 只支持其 Remotion 素材结构，不能用于手绘任务冒充版本迁移。保留既有版本结构，不改成第二套 Windows 项目。

## 2. 将技术资料变成可验证的讲解

先明确受众问题、唯一主张与适用边界。用户提供参考片时参考它的画面语言、节奏和质量，不挪用题材、角色或技术结论。

为核心主张记录“说什么→来源/版本→限定→哪一镜→是否可公开”。技术事实查一手资料，地址、比特、比例或时间等数值独立计算。资料中的预期输出、占位符、待填表格和模拟示意不能写成实际测量或故障已修复。

新脚本优先选择一个可画出的机制：先呈现具体矛盾，再保持同一个对象拆开/改变/对照，最后给观众核对动作。说明必要反例，不泛化某个 API/设备的契约。知识库只读；公开包只放已获授权的公开表达与来源，不复制内部原页、路径、客户信息或日志。

## 3. 两份文字与实际配音

每段保持稳定 `id`，记录：`text`、`spoken_text`、对应 `audio`、页/语义关系及声源。

- `text` 用于准确字幕和技术展示，例如 `0x3C`、`I2C_SLAVE`。
- `spoken_text` 是实际送入合成器的文本，可写“十六进制三C”“I方C地址设置接口”，但不能改变技术含义。保留两者对照，不能直接拿合成器导出的口语化 SRT 当最终技术字幕。
- 技术名词、数字和字母的实际发音仍需试听；文本替换只减少歧义，不能证明发音正确。

用户要求 API 优先时，核对公开接口是否实际提供同款音色。没有确认到就按已授权 GUI 路径继续；不要反复研究通用 TTS，也不调用会静默回退音色的内部接口。2026-10-13 的检索仅“未查到同款公开 API”，不是证明永远不存在。

本例剪映路径及导出核验见 [剪映 GG侠配音参考](../skills/technical-handdraw-video/references/jianying-voice.md)。有准确导出的逐段声音即可走引擎离线合成，无须强制安装 VoiceStudio。没有已授权可用声音来源时，完成不受影响的本地工作并明确缺项，不将无声片称为完成。

## 4. 分镜和横屏原生画面

按完整意思划页，多个语句可以在同一画面累积。固定颜色表达固定概念，空间关系承接解释；别每句话换一张无关插画。六页、十四段和约两分钟只是本次结果，其他主题按实际需要安排。

本例横屏重排在1920×1080设计坐标下设计，再将文字、图示与位置映射到3840×2160重新绘制；没有使用竖版 MP4 作为放大素材。可编辑的数字、公式、位框、箭头必须精确。AI生成插图不承担最终文字准确性。

插画与手部仍可能使用小于4K的原始栅格素材，因此只报告“4K画布与文字/图示”，不报告全部素材原生4K。新图使用当前生图能力；需要编辑位图时用对应图像工具，技术文字和代码图层由程序排版。

按所用手绘引擎读取美术指导、风格与语义分区要求，先查看代表画面再扩展素材。全部轮廓完成后再按部位顺序填色；字形隔离、笔间抬笔，文字/颜色应随笔尖出现。前臂裁切边留在画外，手部不能持续遮住关键结论。不要把整张图淡入称作手绘过程。

从实际字形边界和排版宽度测量，避免长拉丁标识符中间换行、句号落在行首、比特数超出分组背景。字幕作为最后覆盖层，预留独立区域，最多两行；超长时重新分段，不一味缩小字号。

## 5. 用真实声音安排动画

生成或导入旁白后测量每段实际时长与活动区间，再构建 `job.json`、`design.json` 和派生时间线。

- `audio.pace=1.0` 是本次原速选择，不为容纳过密绘图而加快声音。
- 实际活动区间决定字幕起止与动作窗口；音段变动后，后续页时码都要重新生成。
- 动作 `weight` 是相对时间分配，不是秒数。完成后留阅读停顿，过密则减少画面复杂度或合理拆段。
- 可按导演判断不用持续配乐。本例只在语句间加轻提示音；检查间隔足够和末尾淡出，不能只凭配置推断声音不遮挡。
- 去静音须保留起音/句尾并查切边；阈值检测可能漏掉很轻的辅音，不代替听音。不得直接用源配音槽位时码作为最终影片 SRT。

渲染入口和本地适配见 [运行与验收参考](../skills/technical-handdraw-video/references/runtime-and-review.md)。`doctor.ready` 与 `voice_studio.available` 含义不同，已有音频可离线合成。

## 6. 代表段、返工与整片

选择能暴露本片风险的代表段：数字/字母、最长字幕、插画描线填色、手遮挡及换页。先实际查看样段再完整渲染，不把样段文件存在当成审核通过。

本例曾发现七位数字总宽超过底色分组框、读写位间距过近，以及标点落到第二行开头。修布局和字幕断行后重渲染同一代表段，保留失败证据。只改失败层，不放松验证器、不删除字幕来消除报警。

完整渲染后检查最终 MP4，至少覆盖：

| 证据层 | 具体检查 | 不能替代 |
| --- | --- | --- |
| 工程 | 全解码、分辨率/帧率/编码、当前源指纹、时间线/路径、字幕边界 | 观感与技术正确性 |
| 内容/静态画面 | 封面、全部完成页、正确字符和数字关系、限定与可读性 | 动作顺序、流畅程度 |
| 动作/播放 | 每页代表性动作窗、描线→填色、字符显现、换页、全片播放 | 未观察帧的逐帧判断、主观听音 |
| 最终音轨 | 源段对应、末句/切边、混音与编码后对应、响度与削波 | 实际术语发音、自然度 |
| 主观声音 | 实际听完整片或明确试听范围，核对术语、语气与遮蔽 | 作者终稿确认 |

连续播放可以记录 ended、帧数、掉帧/损坏及截图。播放器静音时明确记录；低分辨率联系表不足以核对小字，应另看长字幕等原尺寸局部。抽取10fps代表窗是本次可用方法，不是全片逐帧验收。

`review.json` 绑定实际 `video_sha256`，分别填写 content、visual、motion、audio、privacy、limitations；无听音能力时使用 `audio.scope=text_and_final_track_engineering_only`、`audio_subjective.status=not_checked`。旧审核不能转移到新哈希。通过对应检查后再 `finalize`，不能使用 `runtime_fixture` 作为正式交付。

## 7. 交付与后续

交付至少包括：有声视频、匹配封面、准确字幕、显示稿/合成稿、可编辑任务/设计源、素材与声音来源、审核记录、预览入口与精确文件哈希。可附试听 MP3，必须与当前混音对应。

公开包按白名单打包后重新读取核对文件集、每项哈希和 ZIP 完整性；内部知识库路径、账号/桌面截图、草稿路径及原始诊断日志留在本地工程。制作目录可保留声音源、失败样段和技术证据，但不全目录打包上传。

正式作品仅生产完成、作者尚未确认时状态为 `review`；生产审核通过且单独记录作者确认后才转 `ready_publish`，该状态不含发布授权。测试片按项目生产规则处理并显著标 demo，不能冒充正式稿。引擎 `delivery_review_completed` 不是作者确认或公开发布。后续发布事实独立记录，不能为重跑交付脚本覆盖已有发布状态；只在明确发布任务中路由到 [网页发布 Skill](../skills/douyin-web-publish/SKILL.md)。
