# 抖音网页发布 SOP

适用：已有确认视频的单篇上传、填表、发布和提交后续查。入口是 [douyin-web-publish](../skills/douyin-web-publish/SKILL.md)。Agent 留在 WSL2，复用当前可控浏览器；必要时调用宿主 Windows UI Automation。本文沉淀 2026-10-13 的真实操作，控件和平台条件以现场为准；用户明确授权时可通过官方网页/UI代操作，不提供发布 API、无人值守调度器或账号托管。

## 1. 确定本篇与续跑位置

先读项目说明、账号档案、本篇 `state.json`、当前版本审核/质量/权利记录，以及最近一次 `publication/` 结果。旧版审核、旧账号和其他篇目的授权不能替代本篇。

| 当前指令与证据 | 下一步 |
| --- | --- |
| 仅制作或检查 | 本地交付，不进入后台写入 |
| 仅上传填写 | 完成上传、字段设置与回读，停在最终发布之前 |
| 已明确要求发布确定版本 | 完成准备后直接提交并核验，不重复索取同一授权 |
| 只说“登录好了” | 与前面的授权一起判断，不能单独扩展权限 |
| 上次调用已发出、结果未知，或存在匹配后台条目 | 先核验后台，不另建或重发 |

账号、终稿或发布时间真正有歧义时才补问。用户允许补充标签，只授权补充本篇相关标签，不授权添加无关活动、音乐、合集、带货或其他平台同步。

项目早期“仅本地生产/不做账号操作”的项目内阻断已由后续明确授权撤回；生产 CLI 仍不增加账号或发布接口。平台适用条件沿用 [项目规则](../AGENTS.md) 和 [界面发布通则](../platforms/xiaohongshu/docs/ui-publishing.md) 的证据要求，区分旧结论、最新用户约束和平台条款。技术成功不证明平台许可，用户撤回自己的旧约束也不代表平台条款变更。本文不重新作法律或协议结论。

## 2. 整理文件和发布字段

本地建议沿用以下布局；已有等价记录直接复用，不为满足模板重复生成：

```text
workspace/douyin/<篇目>/
  state.json
  <版本>/                         # 生产源、成片、审核，保留原样
  publication/<日期>-<版本>/
    authorization.json            # 原意、篇目/版本、账号、动作范围
    manifest.json                 # 实际文件、SHA-256、标题、正文、话题
    title.txt / caption.txt
    covers/                       # 平台适配封面及源文件
    evidence/                     # 回读、局部截图、原始错误、调用记录
    result.json                   # 当前平台结果、证据位置、下一步
```

1. 校验实际上传的 MP4 哈希、画幅、分辨率、时长和音轨；与作者授权的版本对应。已有合格质量记录可复用，不重复整套生产测试。
2. 配音以该版本实际输出为准。音色名称、波形或有音轨不能替代主观试听；未听就保留未知。
3. 标题、正文与标签写入清单。项目画幅偏好从账号档案读取；不要把本例的声音、标题、五个标签或标签数量固化为所有视频的规则。
4. 封面单独适配平台。当天页面为横 4:3、竖 3:4；本例使用 1600×1200 和 1200×1600，这些尺寸是可用样例，不是已核实的平台唯一要求。不能将 16:9 视频封面直接居中裁切后漏掉标题或关键数值。
5. 两张封面先在本地查看，再看平台裁切。保留 PNG/SVG 源；同内容 JPEG 可作为上传选项，但无证据表明必须 JPEG。

运行产物、真实账号、后台数据及截图保持 Git 忽略；SOP 只保留方法。不要为沉淀流程自动上传知识库。

## 3. 接通页面和账号

- 先发现现有工具与会话。已有浏览器连接可用就继续；只有需要时才使用 Windows UIA，不为套用本例强制换 Edge。
- 在目标窗口读取页面地址、标题、当前账号和编辑区域。浏览器启动成功或已有登录历史不等于本次后台可控。不能靠访问公开作品链接验证登录态。
- 同一账号在其他平台可能不同名；现场账号与本篇授权一致后才上传。不要将页面上推荐作者或历史作品作者当成当前账号。
- 若需要本人扫码、验证码或处理访问拦截，保留目标窗口由用户完成；收到完成消息后回读账号，继续已有授权。
- 窗口 HWND、PID、控件、坐标均现场发现。坐标只用于刚刚看到的目标控件；窗口移动、弹层变化或焦点丢失后重新定位。

WSL 调用宿主程序、富文本输入和文件选择的具体方式见 [Windows UIA 参考](../skills/douyin-web-publish/references/windows-uia.md)。不要读取或导出浏览器凭证、修改日常浏览器配置、暴露调试端口、关闭其他窗口。

## 4. 上传视频，填写文案与话题

1. 进入官方创作者页面的上传入口，选择清单中的视频。Windows 对话框使用可访问的 Windows 路径，例如 `\\wsl.localhost\<发行版>\home\<用户>\<项目>\<文件>`；不直接填 Linux `/home/...`。仅必要时临时复制本篇素材，复制前后校验哈希。
2. 读取对话框中的完整路径，核对实际文件哈希后打开。等编辑页出现视频预览及上传/处理状态，再记录“已上传”；选中了文件不等于传输已完成。
3. 标题可用原生输入控件的 `ValuePattern` 写入并回读。正文是富文本，应读取完整 `TextPattern.DocumentRange`，不能只取可见前两行。
4. 逐个核对话题实体。本例空格使前几个话题转换为高亮实体，最后一个需点匹配建议；不能看到文字中有 `#` 就认为已添加成功。不误选同名前缀建议。
5. 记录原始正文与受限归一化结果。本例回读含编辑器 `U+200B` 占位符和话题周围 `NBSP`；只在已确认由编辑器插入时处理。保留正文原有英文空格、换行与空段，仅合并末尾话题行的分隔空格。无法解释的差异先修正，不能删除全部空白后宣称逐字一致。
6. 预览中的“某账号创作的原声”是平台归属显示，不证明选用了某个配音音色。

## 5. 分别保存横竖封面

推荐从单张保存开始，便于确认哪一步完成：

1. 打开横封面，上传对应图片，查看裁切、标题与关键内容，再点“完成”。
2. 若提示补充竖封面，可以先选择“暂不设置”完成横封面保存，然后单独打开竖封面。这只是分开保存，不表示最终忽略竖封面。
3. 上传竖封面，查看实际 3:4 预览，再单独保存。
4. 回到主表单，查看两张缩略图和预览中的实际内容。平台显示“封面检测通过”可作为辅助证据，不能替代实际看图。

### 保存卡住时

- 以状态变化为准等待；短间隔查看忙碌状态、按钮是否禁用及错误。一般观察数十秒；连续数分钟无变化时保留截图与时间，开始恢复，不无期限等待。
- 保存仍在进行时不连点“完成”。尝试关闭封面弹层并读取提示；若平台明确提示“未保存的封面编辑效果”，可取消关闭保留编辑，或在本地源已保留时仅放弃此次封面编辑，重新打开。
- 确认上一保存已结束、恢复可编辑或明确未保存后才重试。实际案例中取消关闭后重试仍卡住；退出未保存的封面编辑器，改用相同内容的 JPEG，横竖分别保存成功。
- 该案例同时改变了文件格式与保存顺序，根因未知。不能写成“PNG 不支持”“UIA 一定不能保存”或“JPEG 必然修复”。
- 恢复仅针对封面，不刷新仍含未持久保存内容的整页、不重传视频。主表单出现已保存缩略图后不要继续重传同一封面。

## 6. 声明及发布设置

按本篇事实设置声明。已知使用 AI 插画/旁白时选择页面对应声明，并回读选中状态、确认后的主表单文字。原创、商业关系或授权条件未知且影响必填项时才向用户补充确认，不能拿其他作品的回答代替。

| 字段 | 核验动作 |
| --- | --- |
| AI 声明 | 弹层中选中状态 + 确认后主表单声明；不能只看 UIA 调用返回 |
| 同时发布 | 仅授权抖音时，核验“不同时发布”为 On、“同时发布到”为 Off |
| 谁可以看 | 与本篇授权匹配；公开、好友、仅自己实际值逐项回读 |
| 发布时间 | 即时或指定日期/时间/时区，与用户指令一致；不沿用别篇排期 |
| 保存权限 | 核对现有值，无指令不擅自改变 |
| 合集、音乐、位置、共创、活动、带货 | 仅按本篇需求设置，不接受平台默认推荐作为用户授权 |

本例 UIA `SelectionItem.Select()` 返回后 AI 单选框仍为 false；改用现场坐标点击、回读 true，再确认才生效。跨平台选项视觉上像单选，却暴露为 `CheckBox`；`TogglePattern` 后回读才证实关闭。不得将一次操作“无报错”等同于生效。

## 7. 记录后只提交一次

最终按钮前，保存以下已有核验结果：账号与授权范围、版本/文件哈希、视频状态、两种封面、标题/正文/话题原文及比较结果、声明、可见性、发布时间、跨平台同步、时间和必要截图。

提交记录要区分三个事实，不能只用一个计数器推断结果：

| 阶段 | 记录内容 | 含义 |
| --- | --- | --- |
| 准备调用 | 本篇/版本、操作标识、准备时间、结果 pending | 只证明准备；进程可能尚未触达按钮 |
| 工具返回 | 调用时间、目标按钮、返回/错误原文 | 返回成功也只证明调用，不能证明后台收件 |
| 后台核验 | 核验时间、匹配条目、审核状态、公开链接或 null | 平台实际结果 |

1. 准备阶段落盘后，在当前编辑页唯一定位按钮名“发布”及 Button 类型，确认可操作，再调用一次。不要误选导航“作品发布”。
2. 调用后立即保存工具返回。若调用可能已发出但超时、窗口消失或进程中断，将结果记为未知，先查后台，不再次点击。
3. 只有可证明动作尚未触达平台时，才按实际记录恢复未执行步骤；任何不确定性都先走后台核验。不要将预留 `submit_count=1` 改成 0 来方便重试，也不要把这个值独自当成已提交证据。
4. 常规站内确认弹层按本篇已有事实与授权完成；出现未知且必须承诺的声明时先补齐事实，不编造确认。

### 本地结果字段约定

新记录采用下表；旧记录保留原样，续跑时按证据映射，不批量改写历史字段。`state.json.status` 仍用生产状态机，不能把下表的平台阶段写进去。

| `result.json.stage` | `state.json.platform_submission.stage` | 进入条件 |
| --- | --- | --- |
| `prepared` | 不必写入 | 文件与授权已核对，尚未上传 |
| `uploaded_editing` | `editing` | 已上传，正在填写或保存；封面/设置未完成仍用此值 |
| `submitting` | `submitting` | 已记录本次提交意图，正在调用或等待平台响应 |
| `submission_unknown` | `unknown` | 提交可能已发出，缺少确定结果 |
| `submitted_for_review` | `reviewing` | 匹配后台条目明确显示审核中 |
| `backend_published` | `published_link_pending` | 后台明确已发布，尚未取得公开链接或作者确认 |
| `published` | `published` | 取得对应公开链接或作者明确确认；可登记生产状态 `published` |
| `needs_changes` | `needs_changes` | 平台明确失败或要求修改；保留平台原文 |

最小结果记录包括：

- `version`、`account`、`video_sha256` 或指向这些字段的 `manifest`；绑定本篇素材与账号。
- `uploaded`、`cover_saved`、`fields_verified`、`cross_post_verified`；仅实际验证后为 true，未知为 null。失败时保留当前 `stage` 和具体未完成项。
- `submit_attempt.prepared_at`、`invoke_returned_at`、`invoke_result`、`tool_evidence`；分别保留准备时间、工具返回时间、原始返回/错误及证据路径。尚无返回的字段为 null，不能据此认定未点击。每次恢复保留此前尝试与错误记录。
- `submit_count` 可沿用历史计数，仅作辅助；历史案例在调用前已预留为 1，调用是否发生必须看 `submit_attempt` 或原始工具日志。
- `backend_status`、`backend_verified_at`、`backend_evidence`、`public_url`、`publication`；未观察到的结果留 null，不从按钮返回值填充。`state.json.platform_submission.result` 指向本篇 `result.json`。

只上传任务停在 `uploaded_editing` 并明确 `submit_attempt: null`；封面卡住用 `cover_saved: false`，不新增 `cover_unsaved` 等临时状态。进入 `submission_unknown` 后先查后台；只有证明动作尚未触达平台时才能恢复未执行步骤，无证据不能退回编辑阶段重新提交。审核中、结果未知及链接待取得时，生产状态与 `publication` 按下一节保持。

## 8. 后台核验、结束和续跑

进入“内容管理”，按标题、正文/话题、封面、时长、发布时间共同匹配本篇。置顶旧作品可能排列在最新作品之前；不要把顶部旧条目的“已发布”当成本篇状态。搜索无结果先清空筛选并检查全部、审核中、已发布等实际入口。

- **审核中**：记录已提交审核，不记已公开；`state.json` 生产状态仍为 `ready_publish`，另记 `platform_submission.stage=reviewing`，`publication` 保持 null。可刷新一次核验；已有明确审核中结果即可交付，不无限轮询。
- **后台已发布**：如实报告后台状态，读取实际作品链接。按项目现有规则，得到公开链接或作者明确确认后才登记 `published`；未取得时保留该差异，不把它变成再次提交理由。
- **失败/需修改**：保存平台原文、匹配篇目及时间。内容修改保留旧版，重新检查受影响的审核与授权；不静默循环提交。
- **结果未知**：记录最早异常及最后可知阶段，下次只查原条目；不另外创建相同作品。

公开链接从实际页面读取，不推算作品 ID，不以公众端要求登录否认已核验后台结果。4K 文件上传、视频预览和 GG侠配音来源各有证据范围；没有验证的平台 4K 播放、主观听感或公开可见性不能补写成已通过。
