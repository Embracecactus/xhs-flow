# Self-media workflow

Use this as the coordinator when a request spans stages or must resume existing content work. For a single strategy, writing, or data task, use the specialized skill directly.

## Start from the task

1. Read the user's stated goal, supplied sources, the current task record, and project rules if present.
2. Identify the smallest current stage: plan, research, author, make, package, publish, or review. Do not require an end-to-end workflow for one-stage work.
3. Keep facts, personal judgment, inference, and recommendation distinct. Verify time-sensitive claims from primary or supplied sources.

## Route deliberately

- Account positioning, topic pool, calendar, trends, or competitor research: use `content-strategy`.
- Confirmed theme to platform-native title, body, and visual brief: use `content-authoring`.
- Technical hand-drawn explainers: use `technical-handdraw-video` when installed and appropriate.
- Platform packaging or authorized official-page work: use `multi-platform-publish` when installed; a finished file or author confirmation does not itself authorize an external write.
- Performance evidence and experiments: use `content-analytics`.

If an optional skill is absent, complete only the supported local step or provide a clearly marked manual handoff. Do not invent a publisher, video engine, account, or connector.

## Preserve milestones

Save a first complete draft, approved final, release package, and review only when the user or project requires persistence. Re-read saved files before reporting them. Keep prior confirmed versions; do not overwrite a final silently.

For delivery packages, include only the assets and fields needed by the selected platform: title, body/description, cover or media, tags, disclosures, source/rights notes, and known gaps. Check referenced files exist.

## External actions and closeout

Direction, platform selection, title/final approval, and authorization for an external mutation remain distinct decisions. Check the actual backend state before retrying an uncertain submission. Record whether an item is draft, scheduled, under review, public, or unknown; do not infer public release from a local package.

End with the current stage, verified artifacts, unresolved evidence, and one next action.
