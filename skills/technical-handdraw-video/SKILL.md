# 技术手绘视频

交付有声 MP4、封面、字幕、显示稿/朗读稿、可编辑工程和审核记录。先读取当前项目、任务版本、来源与已有审稿反馈；用户只要脚本或分镜时止于该产物。

## 选择运行能力

读取本机配置或已安装技能，定位 `sweety-handdraw-video`（环境变量 `HANDDRAW_SKILL_DIR` 也可指定）。它是外部依赖，不位于本技能的相对项目路径内。需要渲染时读 [引擎与验收](references/runtime-and-review.md)；需要剪映音色时读 [指定配音](references/jianying-voice.md)。没有引擎可继续稿件，不把无声样段交付为完整成片。

## 制作

1. **技术结论。** 将关键主张映射到一手来源、版本和限定，独立核对计算。原理示意、受控实验和真实硬件结果分别表述，私有源只取已授权公开的表达。
2. **分镜与分集。** 按观众需要覆盖目标，不把“详细讲解”缩成单一知识点。长内容按完整机制/排查层次拆集，各集有闭环和衔接。维持对象、颜色、状态连续，每个动作解释关系。
3. **旁白先行。** 保留技术显示 `text` 与合成 `spoken_text`，按稳定段 ID 对应。指定音色按真实来源核对，不因 API 或服务缺失静默换声；取得实际音频后才锁定时码。
4. **原生画面。** 从当前任务/用户偏好取画幅与分辨率，未给规格时提出适合内容的默认值；不固化某台机器的4K偏好。文字、公式、比特和箭头用可编辑图层。横屏要重排空间，不拉伸竖版成片。
5. **编排。** 用真实音频活动区间生成字幕和动作，逐步描线/填色并留出阅读时间。不要靠加速声音掩盖过密画面。音乐、提示音按需要加入并检查遮蔽。
6. **代表段与全片。** 代表段包含长字幕、术语、画面动作和换页；实际查看通过后完整渲染。最终 MP4 检查每页完成图、动作窗、字幕、首尾及连续播放；声音另外核验。

## 修订与交付

修订保留旧源、音频、输出及审核，新版重新核验受影响的时序和布局，审核绑定实际视频哈希。不把 Remotion 项目的 `flow.py` 强套到另一引擎，也不改验证器放行失败。

工程检查、图像/动作检查、实际听音与作者确认分别记录。无法听时标 `audio_subjective: not_checked`；有波形/ASR/信号相关性不等于音色自然或发音正确。4K画布也不证明每张栅格图原生4K。

按项目现有状态机交付，给出作品入口、规格、声音来源、已做检查与未验收项。已有明确版本的后续发布指令可以确认该版本，但不能补写“作者已听过”。网页发布转 [multi-platform-publish](../multi-platform-publish/SKILL.md)。
