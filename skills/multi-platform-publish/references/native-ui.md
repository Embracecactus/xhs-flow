# 原生界面与文件对话框

优先使用当前环境已有的浏览器/桌面控制工具。浏览器打开不等于接通控制；核对当前窗口、进程、前台状态和目标文档。控件树缺文档时只诊断当前目标，不转储全部浏览器窗口或地址栏。

句柄、PID、屏幕坐标、端口和 Windows 用户目录都在运行时发现，不写入通用脚本。依据文本、角色、所属容器及现场边界定位；同名按钮必须消歧，点击后重新读状态。网页重绘后重新取控件，不能复用旧引用。只读等待可以有限重试；最终提交不自动重试。

单个 GUI 会话一次只允许一个执行者。并行助手只做文案/证据分析，不同时操作窗口。若采用 PowerShell，参数单独传递、UTF-8 文件读写，按宿主政策执行；已允许的场景可用单进程 RemoteSigned，不用 Bypass 或修改全系统策略。平台扫码、验证码和系统拒绝交由用户，不绕过。

Windows 文件对话框使用真实 Windows 路径，可用 wslpath 转换；UNC 路径正确保留反斜杠，不把 shell/JSON 的重复转义直接填入控件。等待对话框存在，再填文件名、回读、点击一次打开；窗口尚未出现时输入可能落入网页正文。无法直接访问时只转存本篇素材并比较 SHA-256。

长文案采用能保持换行的原生输入方式，全文回读而非只看首行。避免 shell 拼接中的反引号、美元符号和命令替换；工具支持结构化参数时优先使用。剪贴板只在可安全保存与恢复时使用。

证据裁掉地址栏、二维码和无关窗口，记录内容与状态而非会话令牌。工具响应成功仅表示调用结束；TogglePattern、InvokePattern 或坐标点击是否改变网页，必须读当前 UI。若平台开关采用受控输入而 TogglePattern 无效，用当前可见原生点击并再读，不循环盲点。
