# 多平台发布

把已确认内容发布到用户指定的平台和账号，并逐项核验后台结果。先读项目规则、内容版本/审核/权利记录和最近发布台账；按实际篇数和平台建立矩阵，不固化集数、账号、标签或日期。

## 输入与授权

确认素材及 SHA-256、标题/正文/固定标签、封面、声明、可见性和带时区的排期。用户已明确的任务和持续授权按原范围复用，不在登录完成或续跑时重复索取；变更账号、作品版本或授权范围时只澄清缺失部分。Skill 本身不能授予权限。只上传、只存草稿的任务不得触发最终发布。

把有限系列排期与无限期运营区分开。平台是否支持定时、可选时间和额度以当前账号界面为准，不把某次成功或旧限制写成永久规则。缺 API 不等于禁止界面操作；若确有适用协议限制，记录官方原文、读取时间和适用理由，不用换工具规避。

## 执行

1. **恢复。** 读取 [记录契约](references/records.md)，匹配作品/版本/平台/哈希。`submission_unknown`、扫码待确认或已提交过的项目先查后台；存在匹配项就续查，不重建、重传或重提。一次失败不改变其他项目状态。
2. **接通。** 复用现有可控会话并现场核对账号。需要 Windows UI 时读 [界面操作](references/native-ui.md)。缺登录或平台验证才请用户完成；不导出凭证，不接管日常浏览器配置。
3. **准备。** 上传准确版本，等上传/处理完成，填写完整文案，保留段落和用户标签；检查标签是否成为平台话题实体。分开保存平台要求的封面，核对原创/AI声明、可见性、同步分发和日期时间。
4. **复核。** 当前界面回读素材、账号、标题/正文、封面、声明和排期。日期操作可能改变通知选项，须再次回读。预览、素材库保存、按钮可点击都不是发布成功。
5. **提交。** 确认最终按钮的所属对话框与语义，最终提交只执行一次。分别记录准备、实际调用、用户验证和后台结果。超时或跳转不明先查后台，不用自动点击重试。
6. **核验。** 在内容管理中按标题、封面、时长和时间匹配，必要时展开折叠记录或清除筛选。审核中和已保存排期可以同时成立；公开链接未知时保留 `null`。报告已上传、已提交审核、后台保存定时、后台已发布及公开链接，不能相互替代。
