# Visual Treatment｜《没插开发板，固件为什么还能跑？》

版本：工程电影导演设计v001。配套：[Artifact Flow](artifact-flow.md)、[Shot List](shot-list.md)。

**只设计，不生成视频、画面、固件或运行结果。** 当前没有本次目标镜像与失败/修订运行证据；下文是待实施的导演设计，不是完成记录。

## 1. 核心视觉命题

把**同一份firmware工程，从输入到有限验证的变化**拍成一条可见、可追溯的工作链。

不是QEMU、CPU、UART逐章介绍，也不是AI能力展示。每一次换镜头，都因为当前对象需要进一步被分析、执行、定位或验证。

“同一个对象”指同一工程的版本谱系，不指修复前后字节相同。原始`firmware.bin`保持只读，修正版另存并记录来源；新的成功不能归给旧镜像。

风格：工业CG＋真实工程记录。禁止人物、卡通、动物、小怪兽、虚构城市、真人剧情和Pixar式表演。

## 2. 空间与对象

### 现实锚点

开场与结尾使用同一桌面、同一空目标板位置。没有手、脸或人物行动。

开场建立“目标硬件尚未到达”的任务前提，结尾空位仍在，但固件工作已有有边界的结果。情绪来自工作推进，不来自人物庆祝。

### 工程记录层

实际文件、分析结果、命令、trace、源码diff与验证记录承担证据。摄影视点进入文件的具体内容，不停留在四个文件图标的轮播。

`firmware.bin`是主身份锚点；配套ELF、链接map和linker提供可解释的结构。它们须来自同一构建，不能用任意文件拼成工程。

### 机制CG层

把记录中相关的地址、状态和设备依赖空间化：装载映射、CPU执行位置、RAM变化、UART条件与宿主输出路径。

这是软件模型示意，不是实体芯片内部、不是真实版图或电流路径。真实记录与CG有清楚的样式边界，后者不能冒充测量。

“文件→模型”是查看同一对象的不同层次，不是进入虚构世界。原文件身份与证据引用在切换中保持可追踪。

## 3. 观看路线

**完整镜像 → 启动入口 → 一次具体访问 → 相关寄存器/模型状态 → 源码改动 → 同条件复跑 → 验证范围。**

先展示整体关系，再深入有依据的问题位置；问题解决后沿原路线复看，最后回到最初空位。

失败段不必出现红色报错。更有力的状态是：执行已经到达某一步，但约定的后续结果没有出现。CPU等待、异常、未抵达入口或UART不就绪必须按实际记录区分，不能一律画成整机停止。

修复与复跑紧邻，中间不插入原理讲座。失败与修订版本尽量保持相同构图，让唯一被验证的变化容易看见。

## 4. AI任务表达

使用Boot Analysis、Memory Analysis、Device Analysis及运行/日志任务标识，不设计机器人或头像。

任务标识紧贴被分析对象，展示具体动作与产物：定位向量、核对映射、观察执行点、比较寄存器条件、提交差异。分析结束后，证据进入下一步，标识退场。

多个窗口只表示不同职责视图。当前默认单Agent，不能表现为多个独立Agent已经并行执行；独立协作只有取得实际调度和合并记录后才可展示。

窗口不同时争夺注意力，不用全屏任务卡替代过程。没有实际产物时，镜头仍是设计稿，不能在成片里播放虚假的完成状态。

## 5. 摄影

- **现实段：** 低位侧滑、克制微距、稳定空位，建立尺度与缺席。
- **分析段：** 文件整体到真实内容位置，构图与后续映射相接。
- **环境段：** 一次总览交代CPU、Memory、Device的关系，此后不重复泛化大场景。
- **定位段：** 从trace对应的执行点进入相关访问，再进入寄存器条件。相机沿证据走，不沿随机光线飞。
- **修订段：** 相同位置比较旧/新状态，实际diff与模型变化对应。
- **复跑段：** 重访失败段的路径与构图，再推进到此前没有发生的结果。
- **结尾：** 验证范围接回同一空位，不以绿色OK或全模型点亮收场。

动作发生时适当稳住相机。景深分离背景，但不能虚化关键地址、状态或接纳动作。允许有动机的剪接，不为“一镜到底”牺牲可读性。

## 6. 材质、光影与细节

基调为石墨灰、陶瓷白、缎面金属；倒角、微粗糙度、接触阴影和受控边缘光建立工程质感。透明截面仅用于暴露关系。

冷色强调当前访问，低饱和暖色强调候选阻塞位置。颜色不是诊断依据，确认原因须有记录。状态由内容与结构变化表达，不靠全场发光。

细节来自真实装载段、映射、代码位置、访问与差异；不添加假机器码、伪日志、装饰波形、性能读数或Agent用量。模型比例、动画时长和示意槽数不代表硅片面积、周期或容量。

可借鉴品牌工程演示的克制与精密，不复制产品造型、固定构图或品牌配色。

## 7. 动画与记录同步

Blender承担工业结构、摄影与机制动作；合成层承担真实记录节选、定位与字幕。两者围绕同一运行事件或状态采样建立关联。

- 装载由实际段与映射关系驱动，不把整个bin魔法般变成CPU。
- PC、Memory、MMIO来自对应运行的观察，不凭时间轴编造。
- 对失败与修订分别从复位开始，不把旧运行的队列或状态延续给新镜像。
- 对采样间没有记录的过程不伪造连续状态；可用明确标注的机制示意补空间理解。
- 加速/节选不伪装实时速度；动画速度不推导性能或真实波特率。

少量原创事件拟音强化顺序，不用角色对白或卡通音效。无需靠长旁白解释每个模块；必要短字幕说明任务和验证边界。

## 8. 技术边界与导演门禁

当前以既有BK7258下游诊断环境为技术基线，匹配机器与镜像；诊断向量建立初始SP与复位处理入口，绕过ROM/Bootloader。ELF的`e_entry`不直接代表本路径起步PC。

`firmware.bin`保留主身份，但执行载体按该模式选择匹配ELF；不能仅因主角叫bin就错误演示其任意装载。bin与ELF对应关系必须核验，raw fallback不作为万能兼容能力。

UART沉默与缺门控目前是候选案例。实际失败若来自别的原因，修改问题段，而不是篡改结果配合分镜。若没有真实故障而采用受控注入实验，明确标注，不能包装为产品事故。

正式渲染前须锁定真实工程身份、可复现运行、原因验证、修订身份与同条件复跑结果。仅有字符输出不足以证明完整启动；结尾须回答：

- **已证明：** 这份修订镜像在这套受控环境中抵达约定路径，满足列明的检查。
- **未证明：** 完整产品启动、全外设、真实电压/波形/时序及实机验收。
- **下一步：** 对应真实目标硬件验证。
