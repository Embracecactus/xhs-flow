# 30秒开场分镜｜同一份固件，第一次获得可验证的运行结果

标题沿用《没插开发板，固件为什么还能跑？》。这是替换v003开场视觉逻辑的导演设计v002，**仅分镜，未生成视频**；不沿用v003的镜头、美术或审核结论。用户本轮范围是重新设计30秒开场。

本片主动作：**文件被识别 → 地址关系成形 → 运行环境接入 → 程序推进 → 输出受阻 → 定位使能遗漏 → 源码修订与重建 → 同条件复跑 → 留下有限验证证据。**

“同一份固件”指同一工程的版本谱系：分析和运行不改变原bin，修订重建后产生新bin。对象的知识结构、运行状态、证据逐步增加，不能表现为一个不变哈希的文件被魔法修好。

## 参考落点与统一空间

依据[本次原片叙事与建模重看](../../../references/process-and-modeling-review-20261012.md)：学习21.5–32.5秒的原位施工、32.5–35.5秒的结构展开、41.5–44.5秒的有落点深入，以及60–63秒的干预对照。参考的重点是工程关系可以从平面转成结构，再变成状态；新片不复制板形、层数、场图或角色。

建立一个以固件为中心的工程画布。镜头可从正投影倾斜成浅三维，局部可剖切；同一地址与字段的邻接关系保持。**这里的空间表达来源、映射和状态关系，不表示物理芯片布局。**

- **输入层**：一张按实际文件偏移排列的薄数据面，先有整体轮廓，分析后才显出分区。不会把400字节挤成400个高低键帽；远景只读分区，近景才露出需要的字节。
- **运行层**：由匹配ELF与linker确定的地址区域，置于输入投影下方。CODE、RAM、MMIO使用断轴分隔；同区域内部保留地址顺序，不把遥远地址画成相邻连续内存。
- **外设局部**：UART是MMIO区内可展开的寄存器截面与单发送缓冲状态，CPU以当前执行位置和状态探针呈现。没有芯片外壳、电脑桌、键盘或装饰性机械结构。
- **证据**：每次观测在对象原位留下短刻线或记录锚点，最后挂接报告。trace是事件及检查点的重建，不能作为电流、真实走线或逐指令连续录像。
- **任务活动**：分析探针在被处理的区域工作，完成后留下分区、映射或观测；不依靠持续闪烁表示“思考”。Memory Analyzer、Boot Analyzer、Device Mapper、Runtime Observer是单Agent的职责标识，片中简写为“布局、入口、映射、观测”，不是多Agent实际调度证明。

输入区位于画面左上，RAM在其下方，UART在右侧，输出记录在UART外沿。开场和结尾保持相同轴向。失败与成功的UART镜头共享构图，其他区域留作暗轮廓，观众能看出是原位置发生了改变。

## 30秒分镜

表内时间为剪辑设计秒数，不是客体执行耗时。全段计划无旁白，以动作成立；声音仅为后续拟音建议，本轮不制作音轨。

|镜头／时间|对象开始 → 结束|具体画面与主要动作|摄影与前后承接|任务及留下的产物|
|---|---|---|---|---|
|01／00–02秒|孤立文件 → 身份确定、等待解析的固件|`firmware.bin · r1`落在深色工程画布中心；薄数据面从文件边缘展开，末端仍收拢。只显文件边界，不先摆好一套环境。目标短句“让它先跑起来”。|近正投影，不做绕物欣赏。展开方向指向下一镜的解析动作。|输入登记；留下r1身份签与固定轮廓。真实输入400字节。|
|02／02–05秒|未解释字节 → 有入口、代码与数据关系的结构|布局与入口探针沿同一数据面移动；64字节向量区、代码区和末端4字节数据各有明确边界。原轮廓不换，分区投影到下方地址坐标；RAM中的BSS只出现空线框。|镜头轻倾，平面变成可读的浅结构；分类结果在原位留下，投影关系带入下一镜。|匹配ELF/linker参与分析；`memory_map.json`成为结构的来源签。没有改写bin，也不从bin臆测BSS。|
|03／05–08秒|结构已知 → 匹配运行环境已就位|已选`QEMU · MPS2 AN385`配置从画布边缘接入；映射探针对准CODE、RAM、UART地址区，既有模型的观察截面按对应位置展开。固件装载投影落入CODE区，RAM运行区仍待初始化。|稍拉宽展示关系，保留上一镜投影位置。环境随映射配准成形，不在旁边另起一组芯片。|环境配置与装载；来源为真实machine配置和命令。模型由已有QEMU支持提供，不是AI从bin自动创造硬件。|
|04／08–11秒|已装载、未执行 → 入口与应用路径已推进|执行探针从向量入口进入代码；`.data`初值从装载位置复制到RAM，原值仍保留；观测锚从reset推进到应用发送前。镜头用一次“复制到位”让观众看出运行开始影响状态。|沿映射关系小幅下移，输入轮廓仍在上缘；最后活动落点朝向UART。|入口与RAM状态记录；重建reset、main、before_tx检查点之间的机制，不伪造中间数值或连续指令流。|
|05／11–15秒|程序已经运行 → 第一次写入滞留、输出为空|跟随真实首字节`F`进入UART DATA缓冲。缓冲占用后没有TX事件；执行探针继续回到STATE轮询位置，缓冲保持占用，右侧输出区仍为空。动作节奏从前进变成重复等待，留一拍空白。|局部推进到UART截面，保留来路与出口。暂时不展示原因标签，先让观众看到“进去了，却没有出来”。|Runtime Observer留下`TXFULL=1`与0字节记录；不是整台CPU死机，也不是无限排队的字符流。|
|06／15–18秒|故障现象 → 可定位的控制条件|镜头在同一UART局部侧移，观察探针从等待记录指向CTRL的使能位；`TX_EN=0`被框出，DATA占用与空出口仍同场。其他区域退为轮廓，问题位置成为唯一焦点。|不切到代码窗口；用截面揭开刚才看不见的控制状态。观众仍能认出镜头05的缓冲和出口。|定位产物挂到该字段，来源是CTRL状态、设备事件及源码对应；故障为受控注入，不包装成未知产品事故。|
|07／18–21秒|故障版本 → 含修订的新版本|定位线连到源码配置的短差异签：`ENABLE_UART_TX 0→1`；随后经过明确的“重建”动作，r1缩成保留的轮廓，r2沿同一工程轴生成。新版数据面长度与入口刻线发生相应小变化。|镜头沿定位线回到对象，不开编辑器场景。构建先完成，新身份再接入；旧运行现场仍冻结保存。|源码差异→独立ELF/bin；r1为400字节，r2为404字节。不是直接改运行中的寄存器，二进制变化也不只保证一个位。|
|08／21–24秒|修订镜像已生成 → 从复位重新抵达同一观察点|r2重新装载；旧运行残影退到对照层，运行区回到新一次复位状态。入口探针重新前进、RAM重新初始化，抵达UART配置处，这次CTRL写入使能值。|压缩重现镜头04的方向和主要动作，随后回到镜头05的精确构图；不能从旧版卡点直接接着运行。|新版reset与before_tx记录；使用新版自己的符号和PC，原机器配置、后端及判据保持。|
|09／24–28秒|相同发送路径 → 有TX事件、真实输出与完成点|相同的首字节`F`再次写入；这次出现TX事件，缓冲释放，字节进入外沿输出记录。后续事件压缩累积为42字节，逐步显出真实首行`Firmware started`，完成点留下记录。|与镜头05同位置同尺度，先保持构图让差异被看见，再轻拉回整体。成功由出口真正产生记录表达。|42个TX事件、42字节UART原始记录与firmware_done；不画物理串口波形，不用宿主补写或semihosting代替。|
|10／28–30秒|有运行结果 → 与镜像身份绑定的有限证据|回到开场轴向：输入、结构、运行痕迹和输出属于同一工程对象；通过的入口/数据/串口记录聚合成验证锚。旁边“实机验证”仍为空轮廓，结束短句“软件先验证，实机待继续”。|停住，让前后变化可比较。没有成品芯片转台，也不让所有区域统一变绿。|有限验证报告绑定r2与运行记录。得到可复核的运行证据，不宣称完整Boot、产品成功或物理验收。|

## 模型必须支持的动作

|模型部件|真实结构依据|必须能表现的变化|避免的误读|
|---|---|---|---|
|固件数据面|r1的64字节vectors、332字节text、4字节data；r2对应64、336、4|按区域识别、保留原位投影、新版本长度及身份变化|不是键盘、PCB、物理Flash或会自行生长的文件|
|地址结构|匹配ELF/linker：CODE位于地址0的SSRAM；RAM位于0x20000000；UART0位于0x40004000|输入到装载区的对应、data初值复制、实际访问落点|不是等距物理布局；断轴不能省略成连续大内存|
|运行状态|五个GDB观测点与真实设备事件|已观测状态出现、已确认复制动作、等待条件反复成立|不凭动画帧数制造CPU指令、执行时间或性能结论|
|UART截面|DATA、STATE、CTRL的真实寄存器关系与CMSDK单缓冲行为|一个字节占用；TX_EN缺失时无发送；新版使能后出现TX事件和释放|不造深FIFO、电子闸门、电流热图或真实硅片内部构造|
|任务探针|已做的分析、配置、运行、定位、构建、检查职责|探针对准对象后留下分区、对应线、观测或修订|不是人物、聊天窗口、五Agent并行记录或“AI思考可视化实录”|

背景低对比，使用薄面、局部剖切、状态线和足够清晰的结构轮廓。只有发生动作的局部获得亮度与细节。切到寄存器近景才露出位和必要值；远景不铺满地址文字。单位和数据仅在影响判断时出现，不制作伪工程微字纹理。

## 节奏、字与声音

前11秒建立对象和运行关系；11–18秒放慢，让“已经启动却没有输出”的冲突被看见；18–28秒紧接改动、重建、复位和结果，28–30秒回收有限结论。失败与成功各给4秒，避免用长篇分析挤掉对照。

每镜只要求观众读懂一个动作。画面短签服务定位；完整哈希、地址表和42字节全文留在证据文档，不要求手机观众暂停阅读。计划持续保留一个小型“受控实验 · 状态重建”标识，含义在发布文案中补足，不把它堆成大字幕。

拟音只对应动作：解析短触声、复制落位声、等待段的重复脉冲、重新构建后的复位节拍、输出恢复后的连续短声。等待时留出明显停顿；完成用节奏释放，不用警报爆炸或宏大成功音压过有限结论。声音为后续设计建议；本轮没有试听参考音轨或制作音轨。

## 本次检查与下一阶段边界

这份方案给10镜分别定义了开始/结束状态、具体动作、空间承接与产物，时长连续相加为30秒。六项要求均覆盖：输入01、分析02、环境03、运行04、问题05–06、修改与状态变化07–10。声音和建模只提出可执行要求，没有生成媒体。

文本及工程证据核对不能证明实际观感通过。30秒内“分析→结构”和“改动→复跑”是否无需解释也能读懂，仍须未来预演检验；未来未达到时应减少次要地址和标签，保持因果动作的时间。**本轮按用户要求停在分镜，不启动灰模、动画或渲染。** 旧v003及其源文件和审核保留。
